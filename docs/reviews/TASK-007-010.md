**`users_after_update` in 003:**
- **Scope:** it now checks only when an active owner is removed, so `last_login_at` writes no longer hit it.
- **Race:** it takes the advisory lock after the row update. Under READ COMMITTED, the second transaction's `not exists` runs with a fresh snapshot after the first commits. The write-skew race is therefore closed.
- **Deadlock:** only row locks on different rows plus one advisory lock are involved, so there is no deadlock cycle.
- **Hardening:** it is SECURITY DEFINER with a pinned search_path and no recursion.
