## Summary

Iteration 2 resolves all three majors from round 1.

1. **Owner lockout (007).** `auth_throttle` now skips the 50/15-min per-email ceiling only for an IP that signed in successfully as that email within 30 days. A stranger can't create that exemption, because it takes a correct password from that IP. The per-(email, IP) limit of 5 and the per-IP limit of 20 still apply everywhere, and with no IP the throttle still stops at 5. Retention is now 30 days and the new indexes cover the throttle and housekeeping queries. `create or replace` keeps the 006 grants.
2. **`encrypt-offsite.sh` under dash.** It is now plain POSIX sh with no pipefail, and the runbook cron line calls it with `/bin/sh`. I confirmed the syntax with `sh -n` under Debian dash.
3. **Plaintext dumps on the server.** This is now an Owner decision recorded in the queue ("no plaintext .sql.gz leaves the server"), and the developer reports a full backup → encrypt → decrypt → restore → verify run. I can't confirm the Owner's decision myself; the human should confirm it at the phase gate.

**Minors from round 1:**
- The new `checkPassword()` helper serves both sign-in and change-password. It locks the IP before the email (fixed order, so no deadlock), counts the attempt before scrypt, and moves the `withAnon` call back into `lib/auth`.
- If creating the new session fails after the password change, the user is sent to `/login?changed=1`. That page shows only a fixed message, so nothing from the URL is echoed.
- `TRUST_PROXY` now defaults to 0 and the runbook says to set it to 1 on the server.
- Not done: the `clientIp()` unit test. That is an accepted minor.

**Reviewer re-run:** typecheck and lint are clean, `npm test` is 49/49, `db:verify` is 79/79 and `test:e2e` is 24/24 on a fresh production build.

The two remaining minors are doc and test hygiene and don't block.
